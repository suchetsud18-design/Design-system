Toast

A brief, auto-dismissing notification that appears at the edge of the screen. Use toasts for low-priority feedback that does not require user interaction — such as confirmations, sync status, and non-critical errors.

Preview

Click a button to trigger a live toast. Each dismisses after 4 seconds or on click of ×. Toasts stack upward when multiple are shown at once.

Usage — shadcn/ui

# Install via shadcn/ui CLI
npx shadcn@latest add toast

Step 1 — add <Toaster /> once to your root layout:

// app/layout.tsx
import { Toaster } from "@/components/ui/toaster"

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        {children}
        <Toaster position="bottom-right" />
      </body>
    </html>
  )
}

Step 2 — call toast() from any component via the useToast hook:

import { useToast } from "@/hooks/use-toast"

export function SaveButton() {
  const { toast } = useToast()

  return (
    <Button
      onClick={() => {
        toast({
          title: "Changes saved",
          description: "Your profile has been updated.",
        })
      }}
    >
      Save
    </Button>
  )
}

// Destructive variant
toast({
  variant: "destructive",
  title: "Something went wrong",
  description: "Please try again later.",
})

// With action button
toast({
  title: "File moved to Trash",
  description: "report-q4.pdf has been moved.",
  action: (
    <ToastAction altText="Undo" onClick={handleUndo}>
      Undo
    </ToastAction>
  ),
})

// Dismiss programmatically
const { id } = toast({ title: "Uploading…" })
// later:
dismiss(id)

Toast vs Alert

Choose the right component for the situation.

TraitToastAlert
PersistenceAuto-dismisses (ephemeral)Stays until user acts or condition changes
InterruptionNon-blocking; appears at edge of viewportInline; part of the page flow
PriorityLow to medium — confirmations, sync updatesMedium to high — validation errors, banners
User action neededNo (optional Undo/action)Often yes (dismiss, fix, navigate)
Example"File saved", "Link copied"Form validation error, server outage banner

Accessibility

FeatureBehavior
role="status"Default variant uses role="status" (politeness: polite). Screen readers announce the message after the user finishes their current action.
role="alert"Destructive variant uses role="alert" (politeness: assertive). Screen readers interrupt immediately — reserve for genuine errors.
aria-liveRadix wires aria-live="polite" / "assertive" to match the role so AT announces updates without focus moving.
aria-atomic="true"Ensures the entire toast content is read as one unit rather than just the changed portion.
ToastAction altTextRequired prop — provides an accessible description of the action for screen readers that cannot see the button label in context.
Close buttonHas aria-label="Close" (auto-added by shadcn). Focus is restored to the element that was focused before the toast appeared.
Focus managementToasts are not focus-trapped — keyboard focus stays on the main content. Users can reach the close button or action by tabbing when it appears.
Auto-dismiss timingWCAG 2.2.1 requires at least 20 seconds for users who need more time, or a mechanism to pause. Default 5 s is acceptable for supplementary info; critical messages should use duration={Infinity}.
MotionSlide animations respect prefers-reduced-motion — Radix replaces them with a simple opacity fade when the preference is set.
Stacking limitLimit visible toasts to 3–5 at once. shadcn/ui enforces a TOAST_LIMIT (default 1) — increase only if your use case genuinely needs simultaneous messages.
