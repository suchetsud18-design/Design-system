Input

A single-line text field for collecting user input. Pairs with Label and a helper/error message to form a complete field. Supports all standard HTML input types and can be decorated with leading or trailing icons.

States

Every state is visually distinct and communicated without relying on color alone.

Usage — shadcn/ui

# Install via shadcn/ui CLI
npx shadcn@latest add input
import { Input } from "@/components/ui/input"
import { Label } from "@/components/ui/label"

// Basic
<Input type="email" placeholder="you@example.com" />

// With label + hint
<div className="flex flex-col gap-1.5">
  <Label htmlFor="email">Email</Label>
  <Input id="email" type="email" placeholder="you@example.com" />
  <p className="text-xs text-muted-foreground">
    We'll never share your email.
  </p>
</div>

// Disabled
<Input disabled placeholder="Cannot edit" />

// With leading icon (wrap pattern)
<div className="relative">
  <Search className="absolute left-3 top-1/2 -translate-y-1/2 h-4 w-4 text-muted-foreground" />
  <Input className="pl-9" placeholder="Search…" />
</div>

// Controlled
const [value, setValue] = useState("")

<Input
  value={value}
  onChange={e => setValue(e.target.value)}
  placeholder="Type here…"
/>

Props

Input forwards all native <input> attributes in addition to the props below.

PropTypeDefaultDescription
typestring"text"Any valid HTML input type: email, password, search, number, url, tel, date, etc.
valuestring—Controlled value. Requires onChange handler.
defaultValuestring—Initial value for uncontrolled usage.
placeholderstring—Hint text shown when the field is empty.
disabledbooleanfalsePrevents interaction; applies reduced opacity and not-allowed cursor.
readOnlybooleanfalseValue is visible and selectable but cannot be changed.
requiredbooleanfalseMarks the field as required for form validation.
onChange(e: ChangeEvent) => void—Fires on every keystroke.
onBlur(e: FocusEvent) => void—Fires when the field loses focus — good for validation.
classNamestring—Additional Tailwind classes merged with the base input styles.

Accessibility

FeatureBehavior
Label associationAlways connect a <label> via htmlFor / id or wrap in <label>. Never rely on placeholder as the only label — it disappears on type.
aria-describedbyPoint to the hint or error message element so screen readers announce it after the label and current value.
aria-invalid="true"Add when the field has a validation error so assistive technology announces the error state.
aria-required="true"Use alongside the native required attribute for maximum AT compatibility.
Error color contrastThe destructive red border meets WCAG AA 3:1 contrast against the white background for non-text UI elements.
Focus ring4px ring offset by 2px ensures a clearly visible focus indicator even on white backgrounds — exceeds WCAG 2.4.11 Focus Appearance (AA).
Disabled stateThe native disabled attribute prevents keyboard focus and interaction. Screen readers announce the field as disabled.
Read-only vs. disabledUse readOnly when the value is meaningful and copyable; use disabled when the field should not be submitted or interacted with.
Icon buttonsTrailing interactive icons (password toggle, clear) must have an aria-label and be keyboard-reachable — do not use a <span> with an onclick.
Placeholder contrastPlaceholder text uses --muted-foreground (hsl 0 0% 45.1%) — passes WCAG AA 4.5:1 on a white background for decorative hint text.
