Introduction

A production-ready component library and token system for building consistent product interfaces. Built on shadcn/ui, grounded in Figma Variables.

What this is

This design system bridges the gap between Figma designs and production code. It starts with a Figma file that defines every color, spacing value, radius, and typographic scale as Figma Variables. Those variables are exported verbatim into a single design-tokens.css file — no rounding, no approximation, no manual translation.

On top of that token foundation sits shadcn/ui: a collection of accessible, unstyled component primitives built on Radix UI. Shadcn's built-in CSS variable system slots directly into our token layer, which means every component automatically picks up the right color, radius, and spacing without any extra wiring.

The result: a system where a designer can change a Figma Variable and a developer can sync that change to every component in the product with a single file replace.

How it works

Design decisions live in Figma. Code consumes them through CSS custom properties. The two never drift apart.

/* Figma Variable: Shadcn/ui/primary → neutral/900 → #171717 */
--primary: 0 0% 9%;                /* stored as HSL triplet */
--primary-foreground: 0 0% 98%;

/* shadcn/ui Button reads these automatically */
.btn { background: hsl(var(--primary)); color: hsl(var(--primary-foreground)); }

Colors are stored as bare HSL triplets — no hsl() wrapper. This is intentional: it lets you compose arbitrary opacity anywhere without creating a separate token. hsl(var(--primary) / 0.5) gives you 50% opacity primary without any extra variable.

Design principles

Zero approximations
Every token value is exported directly from Figma. No rounding, no eyeballing, no manual conversion. If Figma says #0a0a0a, the token says 0 0% 3.9% — the exact HSL equivalent.
Semantic naming
Tokens describe purpose, not appearance. --primary not --gray-900. --destructive not --red-600. This means a full rebrand only requires changing token values, not hunting through component code.
Accessibility first
All semantic color pairs meet WCAG AA contrast (4.5:1 minimum). Primary text on background is 18.7:1. Destructive meets AA at 4.58:1. Color alone is never the only signal for state.
Component integrity
Shadcn/ui component HTML structure and Radix UI behaviour are never altered. All customisation happens through CSS custom properties only — so every accessibility feature, keyboard interaction, and ARIA attribute stays intact.
